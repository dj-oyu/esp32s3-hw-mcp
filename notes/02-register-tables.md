# レジスタ表の抽出（Phase 1）で踏んだ罠

対象: TRM v1.8 の "Register Summary" 46節（コーパス上で 40 節分の表を検出、計 1560 レジスタ行）。
列構成は各章で 4 列（Name / Description / Address / Access）だが、**ページ内の x は章ごとに違う**
（Description が 217 / 246 / 257 の3通り）。列位置は毎ページのヘッダ行から読む。

## 罠1: PyMuPDF の "blocks" は1行のセルを全部つなげる

`get_text("blocks")` は同じ視覚行の4列を1ブロックにまとめて返す（x0 はブロック先頭）。これで列判定を
すると全セルが第1列に入り、オフセットが1件も取れない（初回 1631行すべて offset=None）。**単語単位
（`get_text("words")`）で取り、x は単語ごとに見る。**

## 罠2: レジスタ名が途中で切れる（フォント切替・折返し）

同一行で2語に割れる例: `SENS_` + `SAR_COCPU_INT_RAW_REG`（p332）。行をまたぐ例:
`SYSTEM_EXTERNAL_DEVICE_ENCRYPT_` + `DECRYPT_CONTROL_REG`（p828）。**名前をアンカーに行を作ると、
切れた後半が独立した「INTR_MAP_REG というレジスタ」になる**（実際そうなった）。行のアンカーは
**アドレス**にする（1行に1アドレス）。名前は帯の中の Name 列の行を連結し、`_` の位置で空白なし連結。

## 罠3: 横組み（landscape）の表 — /Rotate 90

第9章（割り込みマトリクス）の表は回転して刷られており、PyMuPDF は**未回転座標**（y が 595 を超える）で
単語を返す。このままでは1行の全セルが同じ列に入る。変換は `x' = mediabox.height - y1`, `y' = x0`
（y1 側を使うのが正しい: ヘッダラベルとデータの x' が一致することを p547 で確認）。
回転ページでは**フッタが左マージン（x'≈31〜43）と右マージン（x'≈804）**に出るので、
`55 < x' < 800` で落とす。落とさないとフッタ語が折返し名前に混ざる（`(Version INTR_MAP_REG` 等）。

## 罠4: ヘッダ行が毎ページには無い／段違い

- p497 にヘッダ、p498 は行のみ（6.14.2）。→ 直前ページの列構成を持ち越す。
- p498 は "Name" だけ 10.8pt 下にずれている（他の3ラベルと同じ行でない）。→ ヘッダ判定の y 許容を
  1行ピッチに広げ、x の順序（Name<Description<Address<Access）で妥当性を担保する。

## 罠5: 列が右寄せの章がある

RNG 章（p921）はアドレス列が右寄せで、ヘッダの Address ラベルより左に値が来る。ラベル基準の列判定では
Description 列に入ってしまい行のオフセットが消える。→ **セルは形で取る**（`0x....` はアドレス、
R/W・RO 等はアクセス種別、残りは説明）。同じ理由で行アンカーも「Name 列より右のアドレス形トークン」。

## 罠6: 同じページに別の表が同居する

p878 は 20.4 のメモリブロック表（Name | Description | Size | Starting Address | Ending Address |
Access）と 20.5 のレジスタ表が同居。**"Address" の直前の語が Starting/Ending/Low/High/Boundary の
ヘッダはレジスタ表ではない**として弾く。

## 罠7: アドレスの意味が章で違う

多くは Table 4.3-3 のペリフェラルベースからの**オフセット**だが、RNG 章は**絶対アドレス**
（`0x6003_507C`）を印字する。`address_is_absolute` フラグで区別し、絶対アドレスを
「オフセット＋ベース」と解釈しないようにする。

## 罠8: ページを共有する節（再解析で行が増殖する）

2.9.1〜2.9.4 は全部 p332 から始まる。節ごとにページ範囲を回すと同じ行を4回出力する。
**ページ単位で1回だけ解析し、(ページ, 名前, オフセット) で重複排除**し、節への帰属は
ページ内の見出し番号（`2.9.1`）の y で決める。見出しは最初のページにしかないので、以降のページへ
持ち越す（これが無いと UHCI/UART や PMS/SYSCON が同じ節に混ざり、同一オフセット衝突として検出される）。
